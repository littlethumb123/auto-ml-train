Harness engineering deck

Why an Auto-ML Harness Is Needed

The bottleneck is not only model quality. It is searching efficiently across a huge experiment space and turning each round into knowledge that can be audited and reused.

Problems
Problem 1

Manual experimentation over an unlimited problem space

  • Feature sets, model families, preprocessing, encoding, imbalance handling, and hyperparameters interact combinatorially.
  • The search becomes slow, serial, and expensive to run rigorously by hand.
  • Teams can stop at locally good but sub-optimal solutions because the full space is too large to search informally.
Problem 2

Experiment knowledge is hard to audit, track, and reuse

  • Results, rationale, and failures often end up scattered across notebooks, scripts, and chat.
  • It becomes hard to reconstruct why a decision was made or what actually changed.
  • Lessons do not reliably transfer to the next project or another data scientist.
Harness response
Solution

Turn model iteration into an auditable learning system

  • Search efficiently: bound the experiment space into one governed round at a time instead of unmanaged trial-and-error.
  • Separate responsibilities: split planning, execution, review, and historical synthesis across dedicated roles.
  • Enforce the rules: use a deterministic driver for approval gates, scope control, verification, rollback, and trigger handling.
  • Preserve the knowledge: store results, dead ends, assumptions, patterns, and strategy memos as reusable campaign memory.
Outcome

More efficient search, less disposable experimentation, and a body of evidence the next project or another data scientist can audit and reuse.

Design patterns

Harness Designs

The harness is not one trick. It is a deliberate set of constraints that shapes how the agent is allowed to think, act, verify, and learn.

01

Contract-first governance

Fix the problem, the data boundary, and the evaluation rules before the campaign starts.

Why: the system should not redefine success mid-search.

02

Producer is not verifier

Planner, Executor, Reviewer, and Historian do not collapse into one opinion.

Why: proposal, implementation, judgment, and synthesis should stay independent.

03

Bounded autonomy

Writable scope, repair attempts, and allowed actions are all explicit.

Why: experimentation should be fast but still reversible and safe.

04

State on disk, not in chat

Campaign memory lives in artifacts, not only in a running conversation.

Why: the next round should reconstruct truth from persistent evidence.

05

Deterministic orchestration around probabilistic agents

The driver owns validation, rollback, and state transitions between roles.

Why: policy and control should not depend on the model remembering to behave.

06

Escalate instead of improvise

Plateaus, anomalies, and contract conflicts route to explicit handling paths.

Why: when evidence is weak or the system is stuck, the harness should change mode rather than guess.

07

Reason strategically, compute tactically

Agents frame the next move, while tools own metrics, anomaly checks, and statistical verification.

Why: language models are good at diagnosis and framing, not at being the final numerical authority.

The harness is repeatable because its design patterns constrain behavior before any single experiment is run.

Verification

How The Harness Verifies Code, Strategy, And Results

The harness does not prove that a strategy is globally optimal. It proves that each accepted step is scoped, checked, and justified.

1 Before execution

Validate the round before it starts

  • Contracts are approved and in force
  • Plan schema is structurally valid
  • Allowed action type is checked
  • Budget and time constraints are enforced
2 During execution

Keep autonomy bounded

  • Write scope is restricted to approved surfaces
  • Repair attempts are capped
  • Driver can inspect diff and commit substance
  • The loop stays reversible when a step goes bad
3 After execution

Judge the result numerically and independently

  • Metrics are parsed from run artifacts
  • Mandatory tools must run
  • Anomaly checks and bootstrap confidence checks apply
  • Noise-floor logic blocks trivial movement from being called progress
4 Across rounds

Protect the integrity of the search

  • Discards roll back cleanly
  • Anomalies pause the loop
  • Plateaus trigger historical diagnosis
  • Contract conflicts escalate instead of being silently worked around
The trust claim is not “the harness always finds the global best model.” The trust claim is “every accepted step had to survive scoped execution, numerical checks, and independent review.”

Search policy

How The Harness Balances Exploration And Exploitation

The harness does not search exhaustively. It allocates scarce experiment budget adaptively using evidence from prior rounds.

Representation

Experiments live in an explicit tree

Each node stores commit, parent commit, strategy class, metric, and verdict. The planner does not browse history informally; it reads a structured search surface.

model feature hyperparameter imbalance ensemble validation error analysis
root → feature branch → kept node
kept node → ensemble branch → champion

Best branch point is the strongest kept commit to branch from.

Scoring

UCB1 by strategy class

UCB1_i = mean_delta_i + c * sqrt(ln(N) / n_i)
  • Observed average improvement and exploration bonus are combined in one score.
  • Untried strategy classes get effectively infinite priority until sampled.
  • Diminishing-return classes are penalized when recent deltas stay below the noise floor.
  • Historian output can override naive search preference when the campaign is stuck for a structural reason.
Phase policy

Budget-aware search

0-30%

30-70%

70-100%

  • Diversify: sample untried strategy classes first.
  • Deepen: follow the highest-UCB1 branches.
  • Exploit: refine, ensemble, or final-tune the champion while preserving a small moonshot budget.

Noise-floor detection tells the harness when a direction is no longer producing meaningful gains.

Search behavior is explicit: diversify early, deepen in the middle, exploit late, and downweight branches that are only producing noise-level movement.
